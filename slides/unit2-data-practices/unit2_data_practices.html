Good Data Practices

When Good Economists Use Bad Data

  • What is the role of the government in times of economic crisis?
  • Question received renewed interest in 2008-2009 financial crisis

When Good Economists Use Bad Data

  • In 2010, economists Reinhart and Rogoff published influential research on government debt and economic growth.

  • Key finding: When a country’s debt exceeds 90% of GDP, economic growth drops dramatically and becomes negative.

When Good Economists Use Bad Data

  • This strongly influenced policy debates worldwide during the Great Recession.
  • It suggested a policy of austerity–cutting government expenditures during an economic crisis–was the correct policy
  • Went against more established, Keynesian policies

Reinhart-Rogoff Results

When Good Economists Use Bad Data

  • However, there was a problem…

  • In 2014, graduate student Thomas Herndon tried to replicate the results for a homework assignment.

He discovered three issues:

  • Some observations were mistakenly excluded
  • Observations were weighed strangely
  • Excel spreadsheet errors — some cells weren’t included in calculations!

Corrected Results (Herndon, Ash, Pollin)

When Good Economists Use Bad Data

When the data were corrected:

  • The dramatic “cliff” in economic growth disappeared
  • The relationship was much more gradual
  • The policy story was very different

The Lesson

Good data practices are fundamental to credible research. No sophisticated technique can compensate for errors in the underlying data.

Good Data Practices

  • It is essential to first get to know your data before you do any analysis

Some questions to ask:

  • How many observations? What is missing?
  • What is the distribution like? Does it make sense?
  • Are there any outliers?

Good Data Practices

  • A few good ways to get to know your data:
  1. Descriptive statistics
    • N: number of observations — any missing?
    • Mean: Average values — is it reasonable?
    • Min/Max: Range — any impossible values?
  2. Visualizations
    • Can also help identify similar issues
    • Bar graphs, scatterplots, etc.

Spotting Problems: An Example

  • Suppose we’re studying education and wages.

  • The raw data might look something like this:

id education wage age
1 16 83 36
2 16 20 34
3 18 166 30
4 12 119 26
5 18 29 31
  • It’s hard to tell if something is wrong by staring at a list of numbers…

Spotting Problems: An Example

  • So let’s look at some descriptive statistics to help:
Variable N Mean Min Max
Education (years) 100 14.2 -5 20
Wage ($/hr) 100 48.2 8 850
Age 100 35.4 22 200

Red Flags:

  • Education = -5 years is impossible
  • Wage = $850/hr seems suspiciously high
  • Age = 200 is clearly a data entry error

Objects and Assignment

  • As an Object-Orientated Language, the logic of R is built around interacting with objects
  • An object is a generic name for anything that is “saved” in R
  • This includes numbers, vectors, functions, or essentially anything else we will interact with or have to reference

Objects and Assignment

  • Store things as an object using the assignment operator <-
  • We can then just recall the object by name to access whatever is saved to it!
  • We can then use it in calculations, functions, etc.
x <- 3
x
[1] 3
y <- 5
y
[1] 5
x + y
[1] 8

Vectors

  • A vector is a sequence of values of the same type
  • We can perform operations on vectors, and it will apply it to each element of the vector
ages <- c(19, 20, 21, 22, 20, 19)
ages
[1] 19 20 21 22 20 19
ages + 10
[1] 29 30 31 32 30 29
primes <- c(1, 3, 5, 7, 9, 11)

ages + primes
[1] 20 23 26 29 29 30

Functions

  • Functions are pre-packaged sets of instructions that perform specific tasks

  • Every function requires we input an argument, which it uses to produce some output

  • The seq() function generates a sequence of numbers:

bb <- seq(from = 1, to = 30, by = 3)
bb
 [1]  1  4  7 10 13 16 19 22 25 28
  • from, to, and by are the arguments of the function
  • We set from = 1 to start at 1, to = 30 to end at 30, and by = 3 to increment by 3
  • Every functions has a different set of arguments
  • We can look up documentation on how to use a function using the ? function

Data Types

  • Every piece of data in R has a type that determines how it can be used
  • The main types are numeric (numbers), character (text), logical (true/false), and factor(categories)
  • Depending on the datatype, functions will operate differently or not at all

Data Types

# Numeric: numbers for calculations
age <- 25
price <- 19.99
temperature <- -5.2

# Math works naturally
age * price
[1] 499.75
price * 1.08
[1] 21.5892
# Character: text strings (always in quotes)
name <- "Boston"
greeting <- 'Hello World'

# But can combine them
paste("Hello", name)  # "Hello Boston"
[1] "Hello Boston"
# Can't do math on characters!
greeting + "3"  # Error!

R Packages

  • R’s real power comes from packages — collections of functions written by others
  • Think of them as “add-ons” that extend what R can do

Two-step process:

  1. Install the package (only do it once!)
  2. Load the package using library() (every time!)
# Step 1: Install ONCE (like downloading an app)
install.packages("tidyverse")

# Step 2: Load EVERY session (like opening the app)
library(tidyverse)

Conditional Assignment with ifelse()

  • Often we want to create a variable whose value depends on a condition
  • ifelse() checks a condition for every row and assigns a value accordingly

Arguments:

  • test: a logical condition (e.g., mpg > 20)
  • yes: value to assign if the condition is TRUE
  • no: value to assign if the condition is FALSE
mtcars |>
  mutate(efficiency = ifelse(mpg > 20, "High", "Low")) |>
  select(mpg, efficiency) |>
  head(6)
                   mpg efficiency
Mazda RX4         21.0       High
Mazda RX4 Wag     21.0       High
Datsun 710        22.8       High
Hornet 4 Drive    21.4       High
Hornet Sportabout 18.7        Low
Valiant           18.1        Low

ifelse() Inside mutate()

  • ifelse() is most powerful when paired with mutate()
  • This lets us create new categorical variables from numeric ones—very useful for group comparisons
mtcars |>
  mutate(
    power_class = ifelse(hp > 150, "High Power", "Standard"),
    weight_class = ifelse(wt > 3, "Heavy", "Light")
  ) |>
  select(hp, power_class, wt, weight_class) |>
  head(6)

case_when(): Multiple Conditions

  • What if we need more than two categories?
  • case_when() lets us chain multiple conditions together
  • Each line follows the pattern: condition ~ value
mtcars |>
  mutate(cyl_label = case_when(
    cyl == 4 ~ "Four",
    cyl == 6 ~ "Six",
    cyl == 8 ~ "Eight"
  )) |>
  select(cyl, cyl_label) |>
  head(6)
                  cyl cyl_label
Mazda RX4           6       Six
Mazda RX4 Wag       6       Six
Datsun 710          4      Four
Hornet 4 Drive      6       Six
Hornet Sportabout   8     Eight
Valiant             6       Six

summarize(): Compute Summary Statistics

  • Purpose: Collapse a data frame into a single summary row
  • Key arguments:
    • ...: summary functions (e.g., mean(), sd(), n())
mtcars |>
  summarize(
    mean_mpg = mean(mpg),
    sd_mpg = sd(mpg),
    n = n()
  )
  mean_mpg   sd_mpg  n
1 20.09062 6.026948 32

group_by() + summarize(): Grouped Summaries

  • Purpose: Split data into groups and summarize each group separately
  • group_by() key argument: the column(s) to group by
  • Pair it with summarize() to get statistics by group
mtcars |>
  group_by(cyl) |>
  summarize(
    mean_mpg = mean(mpg),
    mean_hp = mean(hp),
    n = n()
  )

What is the average MPG for cars with more than 4 cylinders vs. 4 or fewer?

  • Hint: First mutate() a grouping variable, then group_by() and summarize()
mtcars |>
  mutate(cyl_group = ifelse(cyl > 4, "More than 4", "4 or fewer")) |>
  group_by(cyl_group) |>
  summarize(mean_mpg = mean(mpg))
# A tibble: 2 × 2
  cyl_group   mean_mpg
  <chr>          <dbl>
1 4 or fewer      26.7
2 More than 4     16.6

Practice 4

Create a summary table showing the number of cars, mean weight (wt), and mean MPG for each number of cylinders (cyl).

  • Hint: group_by() + summarize() with n(), mean(wt), and mean(mpg)
mtcars |>
  group_by(cyl) |>
  summarize(
    n_cars = n(),
    mean_wt = mean(wt),
    mean_mpg = mean(mpg)
  )
# A tibble: 3 × 4
    cyl n_cars mean_wt mean_mpg
  <dbl>  <int>   <dbl>    <dbl>
1     4     11    2.29     26.7
2     6      7    3.12     19.7
3     8     14    4.00     15.1
